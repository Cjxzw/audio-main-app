# Main Agent 下一版修复改进方案

日期：2026-07-18

## 1. 背景与实机证据

本轮目标是改善 Main Agent 在多步任务中的等待体验、工具可见性和语音表现力，不改变 Main 以快速语音交流为主、重任务后续交给 Hub 执行层的定位。

最新实机日志暴露了两个直接问题：

- 一次音频路由调查连续调用约 11 次工具，全程保持 `thinking=DISABLED`，没有主动申请深度思考。
- 工具调用使消息数从约 21 条增加到 69 条、提示词从约 3500 字符增加到 41000 字符，用户长时间只能看到连续工具调用，没有语音等待反馈。
- 工具卡片显示完整 JSON 参数，长路径和长查询会把完成状态图标挤出屏幕。

定位缓存和反向地理编码拆分已经完成并通过实机验证，不属于本轮主要改造范围。反向地理编码 3 秒超时暂时保留，后续通过埋点采集真实分位耗时。

## 2. 本版目标

1. 工具记录保持单行、紧凑，用户能立即知道正在做什么和是否成功。
2. 快速模式下累计申请第三个业务工具时，App 自动把当前用户回合升级为深度思考。
3. 自动升级不暂停工具、不取消第三个工具、不增加额外 LLM 请求。
4. 自动升级时立即向用户提供一次语音和界面反馈，降低等待焦虑。
5. 当前回合保留完整工具链；后续回合保留足够的工具事实，但避免原始大结果无限膨胀上下文。
6. 个性化 TTS 工具不在本版实现，留到独立版本设计和验证。

## 3. 工具调用记录改造

### 3.1 聊天窗口

聊天窗口不再展示完整参数 JSON，改为：

```text
🔧 查询天气 · 今天                         ✅
🔧 网络搜索 · 明日天气                     ❌
🔧 读取文件 · VoiceAgentService.kt         ✅
```

要求：

- 工具名称、摘要和状态分开渲染。
- 摘要最多一行，超出部分省略。
- 状态图标使用独立固定宽度视图，不能被摘要挤出屏幕。
- 执行中显示进行状态，结束后原地更新为成功或失败，不追加重复卡片。
- 工具摘要由 App 根据工具类型生成，不额外请求 LLM。
- 完整参数和完整结果继续写入诊断日志，不直接展示在聊天窗口。

### 3.2 摘要规则

- 天气：日期和可选地点。
- 网络搜索：截短后的查询词。
- 文件读取/写入：文件名，不显示完整长路径。
- Shell：命令用途或命令首段，不显示完整脚本。
- 定位：缓存、后台刷新、地址解析。
- 代码图谱：查询关键词或符号名。
- 未配置规则的工具：只显示工具名称。

## 4. 第三次工具调用自动升级思考

### 4.1 计数范围

计数器属于单个用户回合，每次新用户输入从零开始。

建议计入：

- 模型实际申请的业务工具调用。
- 成功工具和失败工具。
- 同一批并行工具中的每一个工具。

不计入：

- `request_deep_reasoning`。
- 工具协议修复控制调用。
- 因重复 `tool_call_id` 或重复批次而被阻止、没有实际执行的调用。
- App 内部状态事件。

个性化 TTS 不在本版工具表中，因此本版不涉及其复杂度计数。

### 4.2 自动升级流程

```text
快速模式
  -> 工具1执行并返回
  -> 工具2执行并返回
  -> 模型申请工具3
  -> App 将本回合 thinkingMode 切换为 ENABLED
  -> App 播放一次等待提示
  -> 工具3照常执行
  -> 下一次 LLM 请求使用深度思考模式
  -> 后续工具或最终回答继续正常运行
```

硬性约束：

- 不暂停、不取消第三个工具。
- 不创建虚假工具结果。
- 不为了开启思考额外发起一次 LLM 请求。
- 如果模型已经主动开启思考，自动护栏不再触发。
- 同一用户回合最多自动升级一次、播报一次。
- 回合结束后恢复默认 `thinking=DISABLED`。

### 4.3 并行工具

如果模型在一次响应中并行申请三个或更多业务工具：

- 在执行该批工具前将当前回合切换为深度思考。
- 等待提示与工具执行并行开始。
- 所有工具按既定并行/串行规则正常执行。
- 下一次模型请求使用深度思考模式。

### 4.4 用户反馈

自动升级时同时更新：

- 语音：只播放一次简短等待提示。
- 聊天窗口：显示一条简短系统状态，例如“正在深入分析”。
- 系统通知：更新为“深入分析中”。
- 日志：记录回合 ID、累计工具数、触发工具和触发时间。

等待提示由 App 从固定语句中选择，不调用 LLM：

- 调查搜索：`我再查一下，给我一点时间。`
- 代码排障：`这个问题有点复杂，我仔细看一下。`
- 通用多步任务：`我想一下，稍等。`

提示 TTS 与第三个工具并行执行；进入下一次 LLM 请求前确保提示已经播完，避免和最终结果重叠。

## 5. 思考与工具历史边界

### 5.1 当前回合

当前用户回合内保留：

- 完整业务工具调用名称和参数。
- 完整工具结果。
- 当前深度思考过程所需的 `reasoning_content`。
- 工具调用之间的原始顺序和 `tool_call_id`。

这样深度思考模型能够使用前两个工具结果继续分析。

### 5.2 后续回合

回合结束后不保留：

- `reasoning_content`。
- `request_deep_reasoning` 调用和控制结果。
- 自动升级思考的内部控制事件。

回合结束后必须保留：

- 真实业务工具名称。
- 关键参数。
- 成功/失败状态。
- 核心工具结果。
- 最终助手结论。

### 5.3 工具结果压缩

当前回合继续使用完整结果；写入长期 LLM 历史时进行确定性压缩：

- 每条持久化工具结果设置字符上限。
- 文件读取结果保留文件、行号范围和关键片段。
- Shell 结果保留命令摘要、退出码和输出首尾片段。
- 搜索结果保留摘要和来源 URL。
- 天气、定位、记忆等短结果原样保留。
- 完整原始参数和结果写入独立工具追踪记录，按 `turnId/toolCallId` 查询，不直接注入每次 LLM 请求。

建议初始上限为每条 3000 字符，实机观察上下文长度后再调整。

## 6. 个性化 TTS 工具（本版不实施）

### 6.1 定位

默认正文播报继续使用固定、稳定、略快的 TTS 风格。只有用户明确要求唱歌、角色化表达、特殊情绪或临时音色时，模型才调用个性化播报工具。

建议工具名：

```text
tts_perform
```

建议参数：

```json
{
  "text": "需要播报或演唱的内容",
  "mode": "speech",
  "style": "开心、活泼，像在庆祝好消息",
  "voiceDescription": "年轻、清亮的女声",
  "speed": "fast",
  "volume": 1.0
}
```

### 6.2 校验

- `mode` 使用 `speech`、`singing`、`character` 枚举。
- `speed` 使用 `slow`、`normal`、`fast` 枚举。
- `style` 和 `voiceDescription` 允许受限长度的自然语言。
- `volume` 只控制 App 本地播放增益，必须限制范围并做软限幅。
- 不允许模型传入任意原始 API JSON、模型名、URL 或密钥。
- 工具调用和结果进入日志；聊天窗口只显示模式和简短风格。

### 6.3 播放流程

- 工具由拥有音频状态的 `VoiceAgentService` 执行，不放入通用文件/网络工具执行器。
- 复用 MiMo 流式 TTS 和当前连续 PCM 播放管线。
- `singing` 模式不经过正文句子切分器，完整文本作为一个 TTS 流请求，避免旋律被拆断。
- 工具音频与普通正文播报共用一个串行音频队列，禁止同时播放。
- 工具结果明确告诉模型“音频已经播放”，防止模型再次逐字播报相同内容。

## 7. 观测与日志

新增以下埋点：

- `agent.thinking.auto_escalated`：工具累计数、触发工具、并行批次大小。
- `agent.wait_feedback.started/finished`：等待提示耗时。
- `agent.tool.persisted_chars`：原始结果长度和持久化长度。
- `location.geocode.started/succeeded/timeout/failed`：反向地理编码耗时，用于计算 P50/P95。

日志不得写入 API Key、凭据内容或未经限制的敏感正文。

## 8. 测试清单

### 8.1 AgentLoop 单元测试

- 顺序调用第 3 个业务工具时自动升级。
- 前两次并行、第三次顺序时自动升级。
- 一次并行 3 个工具时只升级一次。
- 模型已经主动升级时不重复升级。
- 控制工具不计数。
- 失败的真实工具计数，未执行的重复调用不计数。
- 第三个工具正常执行，没有额外模型请求。
- 下一次模型请求携带 `thinking=enabled`。
- 新用户回合恢复 `thinking=disabled`。

### 8.2 UI 测试

- 长路径、长查询词不会挤出状态图标。
- 工具执行中状态原地更新为成功或失败。
- 多个工具连续出现时每个工具只占一行。

### 8.3 历史测试

- 当前回合深度思考能看到此前完整工具结果。
- 下一回合看不到 reasoning 和思考控制调用。
- 下一回合仍能看到压缩后的业务工具事实。
- 大型文件/日志工具不会再次把提示词快速膨胀到数万字符。

### 8.4 实机测试

- 复现音频路由调查任务，确认第三次工具调用时有一次语音反馈。
- 确认第三个工具未被延迟或取消。
- 确认最终回答使用深度思考模式且等待期间没有重复提示。
- 采集反向地理编码至少 20 次样本，统计成功率和 P50/P95。

## 9. 建议实施顺序

1. 工具记录单行化和 App 侧摘要。
2. AgentLoop 工具计数与自动思考升级。
3. 等待提示、聊天状态和通知状态。
4. 工具历史分层与持久化压缩。
5. 单元测试、Debug 构建、覆盖安装和实机回归。

## 10. 需要用户确认

以下项目尚需明确：

用户已于 2026-07-18 确认：

1. 个性化 TTS 不纳入本版，后续使用独立版本更新。
2. 长期历史中每条工具结果最多保留 3000 字符，完整记录另存工具追踪文件。
3. 本版工具卡片不支持点击展开完整参数，完整信息通过日志查看。

第三次工具调用自动升级、无额外 LLM 请求、等待提示只播放一次、真实工具事实保留等规则已经定稿，本版没有剩余产品决策项。
