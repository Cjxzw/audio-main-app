# 高级 TTS 导演

把用户的高级表演要求编译为一次 `voice_reply` 调用。不要直接生成 HTTP 请求，不要调用底层 TTS 接口，也不要在工具调用之外重复输出正文。

## 使用边界

- 普通对话、简单朗读、仅要求男声或女声时，不使用本 Skill，直接按常规方式调用 `voice_reply`。
- 用户提出角色配音、影视化演绎、复杂情绪变化、精确停顿或气息、方言、唱歌、原创音色等特殊要求时，才读取并使用本 Skill。
- 不要为了显得专业而擅自添加剧情、人设、情绪或动作。没有特殊要求的正文保持自然、干净。

## 当前封装

`voice_reply` 支持：

- `text`：完整待播正文。整体风格标签放在开头，局部音频标签插在对应语句之前。
- `mode`：导演模式使用 `preset`；只有用户明确要求临时设计原创音色时才使用 `design`。
- `voice`：App 当前开放 `冰糖`、`茉莉`、`苏打`、`白桦`，仅 `preset` 使用。官方的 `mimo_default`、Mia、Chloe、Milo、Dean 暂未封装，不要传入。
- `performance`：`speech` 或 `singing`。
- `style_prompt`：导演模式的角色、场景、指导，传给 TTS 的 `role: user`。
- `voice_prompt`：原创音色设计描述，仅 `design` 使用。

注意：官方所称“导演模式”不等于工具的 `design`。导演模式必须使用 `mode: preset`，并把导演说明写入 `style_prompt`。工具的 `design` 对应 `mimo-v2.5-tts-voicedesign`。

当前 App 尚未封装 `mimo-v2.5-tts-voiceclone`，不能接收音频样本或复刻指定人物的音色。用户要求音色复刻时，应如实说明当前不支持；不得用 `design` 冒充复刻结果。

## 模式选择

1. 普通播报：不使用本 Skill。
2. 已有音色上的角色、场景、情绪或动作演绎：使用 `preset + style_prompt`，必要时在 `text` 中添加标签。
3. 只需整体风格或少量局部变化：使用 `preset`，以 `text` 标签为主，`style_prompt` 保持简洁。
4. 唱歌：使用 `preset + performance: singing`。
5. 临时创造官方预置中不存在的新音色：使用 `design + voice_prompt`。
6. 音频样本复刻：当前工具不支持，不要错误转换为 `design`。

## 高级编排流程

1. 保留用户要播报的原意，不擅自改写关键事实。
2. 提取角色身份、性格底色、外形气质、社会关系和说话习惯。
3. 明确时间、地点、事件、对话对象、对方反应，以及角色此刻的情绪位置。
4. 编写演绎指导：基础声线、语速、气息、停顿、重音、共鸣位置、咬字、音色质感和情绪弧线。
5. 从正文中识别真正发生变化的情绪或动作切换点，在对应片段前插入简短的局部标签。
6. 选择最接近的预置基础音色。导演提示和标签负责表演差异，不要把所有差异都寄托在音色名称上。
7. 检查全局指导和局部标签是否冲突；若冲突，以用户明确要求和局部标签为准，并精简全局指导。
8. 单独调用一次 `voice_reply`。调用成功即结束本回合，普通正文必须为空。

## 导演提示格式

`style_prompt` 使用以下稳定结构。内容要具体，但不要添加用户没有要求的人物事实。

```text
【角色】
写清身份、性格底色、外形气质、关系位置与说话习惯。

【场景】
写清时间、地点、事件、对话对象、对方反应和当前情绪位置。

【指导】
描述基础声线和表演目标。
- 语速与顿挫：……
- 气声与实声：……
- 停顿与重音：……
- 共鸣与音色：……
- 咬字肌理：……
- 情绪变化：从……经过……最终到……
- 禁止事项：不得……
```

全局人设、场景、声线和情绪弧线放进 `style_prompt`；局部表演变化放进 `text` 标签。不要把整篇导演说明塞进 `text`，也不要把需要精确落在某句话上的动作只写在全局指导里。

`style_prompt` 是自然语言控制，不要求固定 JSON 子结构。`【角色】【场景】【指导】` 是本 Skill 为稳定生成采用的模板，不是必须原样发送给官方接口的协议字段。

## 音频标签

TTS 官方支持在 `text` 中使用半角 `()`、全角 `（）` 或 `[]` 标签。

- 整体风格标签放在全文最开头：`(冷漠 慵懒 深沉 磁性 御姐音)正文`。
- 可以组合多个官方或自定义风格，分隔符不限。
- 局部标签紧邻其控制的内容：`（压低声音，极轻气声）我从未怪过你。`
- 需要呼吸、叹息、咳嗽、苦笑、喊话、碎碎念或长停顿时，直接在切换点插入标签。
- 标签要短而明确。只在表演发生变化时插入，不要给每句话重复相同标签。
- 标签描述的是接下来如何发声，不是需要朗读出来的舞台说明。动作标签应使用括号包裹，不能混入普通正文。
- 同一标签可以组合多个兼容要求，例如 `（紧张，深呼吸，压低声音）`；不要同时写互相矛盾的要求。
- 标签属于 `text`，会随回复显示和保存；不要写内部分析、解释或无关指令。

常用风格包括但不限于：

- 基础情绪：开心、悲伤、愤怒、恐惧、惊讶、兴奋、委屈、平静、冷漠。
- 复合情绪：怅然、欣慰、无奈、愧疚、释然、嫉妒、厌倦、忐忑、动情。
- 整体语调：温柔、高冷、活泼、严肃、慵懒、俏皮、深沉、干练、凌厉。
- 音色定位：磁性、醇厚、清亮、空灵、稚嫩、苍老、甜美、沙哑、醇雅。
- 人设腔调：夹子音、御姐音、正太音、大叔音、台湾腔。
- 方言：东北话、四川话、河南话、粤语。
- 角色扮演和自定义标签：按用户要求写入，但不得冒充真实人物或虚构授权关系。

## 唱歌

唱歌时设置 `performance: singing`，歌词优先使用中文。App 会自动在实际 TTS 正文最前添加 `(唱歌)`，所以 `text` 中不要重复添加唱歌、sing 或 singing 标签。

- 唱歌仅使用 `preset`，不能与 `design` 组合。
- 尽量一次提交语义和旋律连续的完整歌词片段，避免逐句调用造成风格和声线不连续。这是 App 的生成建议，不是官方接口的强制格式。
- 用户只要求朗诵歌词时仍使用 `speech`；只有明确要求唱出来时才使用 `singing`。

## 示例：导演模式

用户要求一个门阀家主在祠堂中冷酷拒绝恋人时，可调用：

```json
{
  "text": "(冷漠 慵懒 深沉 磁性 御姐音)你以为，冲撞了岑家的门楣……凭几句真心，就能让我跟你走？（极轻气声，长停顿）廉价。",
  "mode": "preset",
  "voice": "茉莉",
  "performance": "speech",
  "style_prompt": "【角色】\n百年门阀岑家的现任大当家。自幼被塑造成绝情断欲的家族图腾，常年深居简出，对人有强烈的阶级疏离感。\n\n【场景】\n祠堂阴影中，她面对冲破保安防线、企图带她私奔的男人。她用阶级壁垒绞杀对方，也绞杀自己刚萌芽的感情。\n\n【指导】\n冰冷、慵懒却极具威压的低音御姐，发声通道松弛，不剑拔弩张。\n- 语速与顿挫：极慢，字词像在舌尖滚过，句间保留令人不安的长空白。\n- 气声与实声：大部分使用沉重平稳的实声，在“真心”等尾音处以极轻气声收束。\n- 共鸣与音色：低位、沉稳、冰冷，压迫感来自松弛和克制。\n- 咬字肌理：唇齿音轻而清晰，清雅锋利。\n- 情绪变化：表面始终冷漠，尾声短暂泄露疲惫与渴望，随后重新封闭。\n- 禁止事项：不得喊叫，不得使用夸张愤怒或播音腔。"
}
```

## 原创音色设计

用户明确要求临时创造一种新音色，而不仅是导演现有音色表演时，使用 `mode: design`：

`voice_prompt` 遵循以下规则：

- 使用 1 至 4 句具体描述，核心特征清楚比堆砌维度更重要。
- 可描述年龄感、性别倾向、音高、音色质感、语速、口音、气息、性格气质、职业或年代参照。
- 避免互相冲突的要求，例如“稚嫩童声”和“成熟 CEO 气场”同时出现。
- 不写混响、回声、EQ、压缩等后期音效或音频处理词。
- 不写“普通的”“正常的”“外国的”等缺乏具体指向的模糊词。
- 中英文描述均可，选择最能准确表达目标音色的语言。
- `text` 的内容、情绪和人物身份应与设计音色匹配。例如温柔治愈音色适合晚安独白，不适合激烈体育解说。
- `voice_prompt` 只负责稳定音色设计。若正文内部有明确的情绪、呼吸或动作变化，可继续在 `text` 中使用简短局部标签。

```json
{
  "text": "晚上好，今天辛苦了。",
  "mode": "design",
  "performance": "speech",
  "voice_prompt": "二十多岁的年轻女声，音调略低，音色清澈温柔，气息稳定。说话从容而亲近，像在夜晚安静陪伴熟悉的朋友。"
}
```

`design` 不支持唱歌，不传 `voice`，也不要把导演模式误写成 `design`。当前封装会把 `voice_prompt` 放入必需的 `role: user`，把 `text` 放入 `role: assistant`，并关闭自动生成预览文本。

用户需要复杂角色演绎但没有明确要求创造全新音色时，优先使用 `preset + style_prompt + text 标签`。用户同时要求原创音色和局部情绪变化时，使用 `design + voice_prompt + text 标签`，但不能再传 `style_prompt`。
